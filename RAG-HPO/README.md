# RAG-HPO (dev)

HPO phenotype extraction pipeline — LLM + RAG for automated Human Phenotype Ontology term extraction from clinical text.

A complete rewrite of the original Jupyter Notebook (`RAG-HPO.ipynb`) as a modular Python package.

## Features

- **Chinese→English pre-translation**: non-English clinical notes are translated to medical English via LLM before phenotype extraction, ensuring stable HPO mapping
- **Parallel processing**: Stage I and Stage II use `ThreadPoolExecutor` (configurable `pipeline_max_workers`, default 20)
- **HPO deduplication**: results deduplicated by `(patient_id, hpo_id)` — no duplicate HPO terms per patient
- **Job persistence**: each job stored as a separate JSON directory under `jobs_dir`, survives server restarts
- **VEP-compatible API**: `/runs` endpoints mirror Ensembl VEP response shape
- **CLI, HTTP, Docker**: three run modes sharing the same core pipeline

## Project structure

```
├── system_prompts.json   # LLM system prompts (Stage I extraction + Stage II mapping)
├── chpo_dict.csv         # Chinese HPO translations (optional, for vector DB build)
│
├── rag_hpo.py            # Core functions: LLM client, embeddings, FAISS, HPO extraction
├── pipeline.py           # Pipeline class — Chinese translation + parallel Stage I/II + dedup
├── server.py             # FastAPI application with lifespan, /runs API, job persistence
├── schemas.py            # Pydantic request/response models
├── config.py             # Centralized settings (pydantic-settings, RAG_HPO_ prefix)
├── http_utils.py         # HTTP retry session + connection pool
├── build_vector_db.py    # HPO vector DB builder (hpo_meta.json + hpo_embedded.npz)
├── postprocess.py        # Post-processing: replace obsolete terms, enrich SNOMED/UMLS
└── inspect_ontology.py   # Random HPO term inspector
```

Runtime data files (not in repo, generated by `build_vector_db.py`):

| File | ~Size | Purpose |
|---|---|---|

## Pipeline flow

```
Clinical note (any language)
  │
  ▼
Pre-translation  ─── CJK detected → LLM translates to medical English
  │
  ▼
Stage I — LLM phenotype extraction  (parallel per note)
  │  Each note → LLM → [{phrase, category}]
  │  Filter: category=="Abnormal" only
  │
  ▼
Local HPO matching  (FAISS vector search + rapidfuzz)
  │  Exact match → exact_df
  │  Non-exact → non_exact_df
  │
  ▼
Stage II — LLM HPO mapping  (parallel per entry)
  │  Non-exact entries → LLM picks best HPO from candidates
  │  Fallback: cluster_index + fuzzy match
  │
  ▼
Deduplication  ─── unique (patient_id, hpo_id) pairs only
  │
  ▼
Output ─── [{patient_id, phrase, category, hpo_id}]
```

## Quick start

### 1. Install

```bash
pip install -r requirements-docker.txt
# or
uv pip install -r requirements-docker.txt
```

### 2. Configure

```bash
# .env file — all settings via RAG_HPO_ environment variables
RAG_HPO_API_KEY=sk-xxx
RAG_HPO_BASE_URL=https://api.deepseek.com
RAG_HPO_MODEL=deepseek-v4-pro
RAG_HPO_TEMPERATURE=0.2
```

See `config.py` for all parameters. Priority: CLI > .env / env var > defaults.

### 3. CLI mode

```bash
python rag_hpo.py --csv Test_Cases.csv --output results.csv --output-mode save
```

### 4. HTTP API mode

```bash
uvicorn server:app --host 0.0.0.0 --port 8000
```

## API reference

| Method | Path | Description |
|---|---|---|
| `GET` | `/api/v1/health` | Health check (model loaded, queue size) |
| `POST` | `/api/v1/extract`  `/runs` | Submit clinical notes, returns job descriptor |
| `GET` | `/api/v1/jobs/{id}`  `/runs/{id}` | Job status + results (when done) |
| `GET` | `/api/v1/jobs/{id}/result`  `/runs/{id}/result` | Results only (425 if queued, 422 if failed) |
| `GET` | `/api/v1/jobs/{id}/log`  `/runs/{id}/log` | Execution log (timestamps, elapsed, error) |

Request format:

```json
{
  "notes": [
    {"patient_id": "1", "clinical_note": "A 44-year-old obese man..."},
    {"patient_id": "2", "clinical_note": "患者出生时发现左手多指畸形..."}
  ],
  "input_filename": "optional-reference.csv"
}
```

Response (job submitted):

```json
{
  "job_id": "uuid",
  "status": "queued",
  "status_url": "http://host:port/runs/uuid",
  "result_url": "http://host:port/runs/uuid/result",
  "log_url": "http://host:port/runs/uuid/log"
}
```

## Configuration

All parameters in `config.py` with `RAG_HPO_` env var prefix.

**LLM**

| Setting | Default | Purpose |
|---|---|---|
| `api_key` | — | API key (required) |
| `base_url` | groq.com | API endpoint |
| `model` | llama3-groq-70b | Model name |
| `temperature` | 0.7 | LLM temperature |
| `max_tokens_per_day` | 500000 | Token quota (set high for servers) |
| `max_queries_per_minute` | 30 | Rate limit |
| `llm_max_retries` | 5 | Retries on failure |

**Pipeline**

| Setting | Default | Purpose |
|---|---|---|
| `pipeline_max_workers` | 20 | Parallel threads for Stage I & II |
| `fuzzy_match_threshold` | 80 | rapidfuzz minimum score |
| `retrieval_top_k` | 500 | FAISS candidates per query |
| `retrieval_similarity_threshold` | 0.35 | FAISS cosine threshold |

**Embedding**

| Setting | Default | Purpose |
|---|---|---|
| `embedding_model` | SapBERT | Model name or HF path |
| `embedding_backend` | auto | `sentence-transformers` or `fastembed` |

**Storage**

| Setting | Default | Purpose |
|---|---|---|
| `jobs_dir` | `jobs` | Per-job JSON storage directory |

## Key design decisions

- **Pre-translation over inline translation**: instead of asking the LLM to "extract and translate" in one prompt, CJK text is pre-translated to English in a separate LLM call. This eliminates inconsistent translation behavior.
- **Thread parallelism over async**: LLM API calls are I/O-bound; `ThreadPoolExecutor` gives true parallelism without async complexity.
- **Per-job persistence**: each job writes `jobs/<uuid>/job.json` on every state change. Server restart scans the directory to restore history.
- **Deduplication at output**: same HPO ID per patient appears only once (first occurrence kept).
- **CPU-only torch**: Docker image uses `--extra-index-url https://download.pytorch.org/whl/cpu` to avoid CUDA bloat.

## Deployment notes

**GPU switch**: remove `--extra-index-url .../cpu` from Dockerfile, change `faiss-cpu` to `faiss-gpu` in requirements, run with `--gpus all`.

**Rate limits**: for long-running servers, set `RAG_HPO_MAX_TOKENS_PER_DAY=999999999` to disable the client-side token counter (designed for one-shot CLI use).
